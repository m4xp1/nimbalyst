# Форк Nimbalyst 0.79.1+m4xp1.1

База: upstream v0.79.1, 2535d61ca9060a43c50335501380f4c1664047aa. Windows 11 x64.

## Изменения

- Удалена мишень возле FILES. Имя файла в строке пути раскрывает дерево и выделяет документ.
- Папки в строке пути открывают меню своего содержимого. Доступны переходы в папки/вверх, открытие файла, клавиатура, Escape и закрытие снаружи.
- CONTENT файловой карточки трекера использует TabEditor и общий DocumentModel: сохранение в Markdown, frontmatter и обработка внешних изменений — по существующему файловому пути.
- BM25/recall понимают Unicode, NFC, регистр и ё/е. Миграция меняет только sparse_terms и версию словарного индекса: vectors и их профили не сбрасываются, embedding API не вызывается. Морфология/лемматизация не добавлены.
- Memory Settings → Additional Markdown sources: файл, папка или glob, предварительный список, исключения и Apply. Правила дополняют встроенные источники; перекрытия сохраняют встроенную классификацию. Настройки локальны для проекта в userData расширения; Git их не переносит.
- Добавлены состояния сканирования, обработанные/сохранённые файлы, активность наблюдения и безопасные категории ошибок. Процент vectors относится только к сохранённым chunks. Неизвестные количества обозначаются Unknown.

## Источники и расходы

Правила относительны workspace. Служебные/generated каталоги, архивы и очевидные файлы секретов исключаются; дополнительные источники не выходят за workspace через ссылки. Фильтры имён не обнаруживают любые секреты в тексте. Существующий personal harness-memory root сохранён.

Новые/изменённые файлы получают embeddings от действующего провайдера. При OpenAI выбранный текст отправляется OpenAI. Preview и Refresh сами embeddings не запрашивают. Rebuild сканирует источники, переиспользует неизменные embeddings той же модели и достраивает новые/изменённые данные. Дополнительные источники проверяются на появление новых файлов каждые 3 секунды, без рекурсивного наблюдения всего workspace.

Отдельного lexical режима запросов, кэша запросов и диагностики расходов нет: при активном OpenAI обычный поиск может обращаться к API. Retry/backoff и восстанавливаемая очередь не добавлены. Отказ embedding API может остановить сохранение нового текста; первоначальный сбой может оставить наблюдение выключенным. Исправьте причину и выполните Rebuild; автоматическое восстановление не обещается. Смена embedding-модели сохраняет исходное поведение сброса dense индекса.

## Версия и установка

Версия приложения/About: 0.79.1+m4xp1.1; Windows FileVersion: 0.79.1.1. Тег v0.79.1+m4xp1.1 отличает этот выпуск от upstream. Следующие ревизии на этой базе получают +m4xp1.2 и далее.

Сборка выпускается из release только для Windows x64. Предыдущий v0.79.1 сохраняется. Updater получает уведомления из nimbalyst/nimbalyst без autoDownload и autoInstallOnAppQuit. Установку выполняет владелец вручную.

[Инструкция проверки установленного приложения](FORK-SEARCH-ACCEPTANCE-v0.79.1-m4xp1.1.md). Автоматические проверки механики не заменяют эту приёмку и качество настоящей embedding-модели.
